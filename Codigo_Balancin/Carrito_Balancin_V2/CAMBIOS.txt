[2026-10-20] 7. MPU6050, controlador de ángulo y controlador de giro
---------------------------------------------------------------------
mpu6050.h / .cpp (nuevo): driver I2C (SDA 12, SCL 11, 0x68, 400 kHz).
  - SMPLRT_DIV = 1  -> 1 kHz / (1+1) = 500 Hz.
  - CONFIG DLPF_CFG = 2 -> giroscopio 98 Hz, acelerómetro 94 Hz.
  - Giroscopio ±500 °/s, acelerómetro ±2 g.
  - Calibración del offset del giroscopio al arrancar (500 muestras, ~1 s).
imu.h / .cpp (nuevo):
  - Ángulo de inclinación con filtro complementario a 500 Hz
    (TAU = 0.25 s -> alfa = 0.992).
  - Velocidad de caída = giroscopio en EJE_RUEDAS.
  - Velocidad de giro = giroscopio en EJE_VERTICAL (Z), promediada en la
    ventana de 100 ms del lazo de giro.
  - Ejes y signos configurables en config.h (EJE_RUEDAS, EJE_VERTICAL,
    SIGNO_ANGULO, SIGNO_GIRO); el signo del acelerómetro se deduce de los
    ejes para que sea coherente con el giroscopio.
controlador_pd.h / .cpp (nuevo): PD con derivada medida y saturación.
controlador_pi.h / .cpp: se agrega ControladorPIPosicional (giro); con
  Ki = 0 es un P puro. El PI de los motores no cambia.
lazo_control.h / .cpp (reescrito): tarea multitasa en el núcleo 1, base 2 ms:
  - cada 2 ms:   lectura del MPU + filtro + supervisión de seguridad
  - cada 100 ms: giro, e = VEL_GIRO_REF - vel_giro -> u_giro (±20 rpm)
  - cada 20 ms:  ángulo, rpm = Kp*(ang - ANGULO_EQUILIBRIO) + Kd*vel_caida,
                 saturado a ±60 rpm
  - cada 10 ms:  PI de motores con ref1 = rpm + u_giro, ref2 = rpm - u_giro
  - El giro se suma a la REFERENCIA de RPM de cada motor (no al voltaje):
    si se sumara al voltaje, el integrador del PI de velocidad lo anularía.
  - Seguridad: fuera de ±30° o con 5 lecturas fallidas seguidas del MPU se
    apagan motores y se reinician los controladores; se reanuda dentro de ±5°.
  - iniciarLazoControl() ahora inicia el MPU y devuelve false si no responde.
motor.cpp: controlarVelocidad() ya no reinicia el PI cuando ref == 0
  (con el balanceo la referencia cruza 0 constantemente); solo con reiniciar.
config.h: nuevas secciones TIEMPOS DE MUESTREO, CONTROLADOR DE ANGULO,
  CONTROLADOR DE GIRO y MPU6050. Ganancias de ángulo y giro en 0 (por sintonizar).
main.cpp: mensajes de calibración/estado; se quita la comunicación Serial.


[2026-10-20] 8. Interfaz web de control
----------------------------------------
pagina_web.h (nuevo): página única HTML/CSS/JS sin librerías externas (la red
  del carrito no tiene internet; las gráficas se dibujan en <canvas>).
  1. Botón de encendido/apagado de motores + indicadores pequeños: conexión,
     MPU con/sin señal, ángulo en/fuera de límites y estado con el motivo
     de paro (apagado, esperando vertical, caída, MPU sin señal).
  2. Gráficas de los últimos 10 s (contraíble): ángulo (set point y medido)
     y RPM (set point y medida) con selector Ambos / Motor 1 / Motor 2.
  3. Constantes (contraíble): Kp, Kd y set point del controlador de ángulo;
     Kp y Ki del controlador de giro. Botón Aplicar.
  La página consulta /datos cada 200 ms.
servidor_web.h / .cpp (nuevo): WebServer del core en una tarea del núcleo 0
  (prioridad 5, debajo de WiFi y lwIP), puerto 80. Rutas: /, /datos,
  /motores (POST), /parametros (GET/POST).
lazo_control.h / .cpp:
  - Habilitación de motores (habilitarMotores). Al arrancar los motores
    están APAGADOS hasta pulsar el botón en la web.
  - Estado público (EstadoControl) con el motivo de paro (MotivoParo).
  - Ganancias de ángulo/giro y set point de ángulo ajustables en caliente
    (ParametrosControl); el integrador del giro no se borra al cambiarlas.
  - Cola de muestras (una cada 20 ms: set point y ángulo, ref y rpm de
    cada motor); si se llena se descarta la más vieja.
  - Los datos compartidos entre núcleos se protegen con un portMUX.
  - Si el MPU no responde al iniciar, la tarea de control arranca igual (con
    los motores apagados) para poder mostrar el estado en la web.
  - Los límites de caída/rearme se miden respecto al set point de ángulo.
config.h: nueva sección INTERFAZ WEB (WEB_PUERTO = 80, TAMANO_COLA_MUESTRAS = 150).
main.cpp: arranca el servidor web después del WiFi.
Nota: los cambios de constantes desde la web NO se guardan al reiniciar
  (escribir en flash detiene momentáneamente ambos núcleos); una vez
  sintonizadas, copiarlas a config.h.

[2026-10-20] 10. Botón de calibración (GPIO14) con guardado en flash
---------------------------------------------------------------------
Rutina al pulsar (botón GPIO14 a GND, pull-up interno):
  1. Solo arranca con los motores apagados; si están encendidos se rechaza
     y la web pide apagarlos.
  2. Espera 1.5 s (CAL_ESPERA_MS) con un indicador parpadeando en la web.
  3. Toma 500 muestras cada 2 ms (1 s) acumulando giroscopio y acelerómetro.
  4. Si la desviación estándar del giroscopio supera 0.5 °/s en algún eje,
     cancela y la web indica el error y pide repetir.
  5. Bias del giroscopio = promedio; ángulo de equilibrio = ángulo del
     acelerómetro promediado (pasa a ser el set point de ángulo).
  6. Guarda ambos en la flash (NVS, espacio "balancin").
Archivos nuevos:
  boton.h / .cpp           lectura por sondeo cada 2 ms con antirrebote de 20 ms
  calibracion.h / .cpp     máquina de estados de la rutina (corre en la tarea de
                           control, núcleo 1, usando las mismas lecturas del MPU)
  almacenamiento.h / .cpp  guardar/cargar calibración con Preferences
Cambios:
  config.h: sección BOTON DE CALIBRACION (pin, antirrebote, tiempos, umbral).
  mpu6050: obtenerOffsetGiro() / fijarOffsetGiro().
  imu: iniciarIMU(biasGiro) usa el bias guardado o calibra si es NULL;
       nuevas ultimaLecturaIMU(), anguloDesdeAcelerometro(), fijarAnguloIMU().
  lazo_control:
    - Al arrancar carga la calibración de la flash: si existe, usa ese bias
      y ese ángulo de equilibrio y ya NO calibra el giroscopio al encender
      (no hace falta tener el carrito quieto). Si no existe, calibra como antes
      y usa ANGULO_EQUILIBRIO de config.h.
    - Nuevo motivo de paro PARO_CALIBRANDO. Durante la calibración los
      motores se apagan y el botón de la web no los enciende; al terminar
      quedan apagados.
    - Tras escribir en la flash se reinicia la referencia de tiempo de la
      tarea para no recuperar de golpe los ciclos perdidos.
  servidor_web: /datos agrega "cal" (estado) y "ctxt" (texto del indicador).
  pagina_web: indicador de calibración (parpadea mientras espera/muestrea,
    verde al terminar, rojo en error; se oculta a los 10 s). El botón de
    motores se deshabilita mientras calibra. Al calibrar bien se recarga el
    set point de ángulo en el formulario.
  main.cpp: los mensajes de calibración al arrancar los imprime lazo_control.
